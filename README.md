## ❗ Problema

A transportadora possui dificuldade para acompanhar de forma organizada a
disponibilidade e o desempenho dos motoristas agregados. A falta de uma visão
centralizada das viagens, custos, valores de frete e rentabilidade dificulta a
identificação dos motoristas mais disponíveis e das operações que apresentam
melhores resultados financeiros.

## ✅ Solução

Desenvolver um sistema que centralize as informações dos motoristas e permita
acompanhar viagens, disponibilidade, custos e rentabilidade. A aplicação também
poderá gerar indicadores e rankings, facilitando a escolha de motoristas para
novas operações e auxiliando a empresa na tomada de decisões.



## 📋 DoR (Definition of Ready) & DoD (Definition of Done)

### Definition of Ready (DoR)

- A demanda está escrita no formato de história de usuário, deixando claro
  quem é o usuário, o que ele precisa e qual valor/benefício será gerado.
- Os critérios de aceitação estão definidos de forma objetiva e verificável,
  permitindo que a equipe saiba exatamente quais condições precisam ser
  atendidas para considerar a história concluída.
- Escopo detalhado e claro.
- Todos os materiais necessários para o desenvolvimento estão disponíveis,
  quando aplicável, como layouts, mockups, protótipos, documentação técnica, etc.
- As dependências necessárias para desenvolver a história foram identificadas
  e, quando existirem, possuem condições para serem atendidas. Não há
  dependências externas que bloqueiem o início do trabalho sem previsão de
  resolução.

### Definition of Done (DoD)

- Todos os critérios de aceitação foram atendidos.
- Funcionalidade implementada, testada e sem bugs críticos.
- Código versionado seguindo o padrão da equipe.
- Pull Request aprovado.
- Código integrado ao repositório remoto.
- Funcionalidade validada pela equipe.
- Documentação técnica atualizada.

## 🌿 Estratégia de Branch

O **GitHub Flow** foi a estratégia escolhida por ser fácil e rápida de
trabalhar, perfeita para equipes pequenas, além de se adequar a projetos que
não são construídos através de versões. O GitHub Flow possui algumas regras
básicas:

- A branch `main` é sempre deployable.
- Nova branch para cada nova feature.
- Commits com mensagens simples e claras.
- Pull Requests para features concluídas.
- Merge das branches caso tudo esteja de acordo.
